Prepared November 9, 2026; updated November 13, 2026. It describes the system as it runs today: the hub, its apps, the three-computer cluster and the home network. Passwords, keys and private addresses are deliberately left out.

1. The big picture in one page

Home Lab Hub is a private "front door" to a family business's software and to the house's cameras and smart devices. Sign in once at hub.energiapower.llc and you see a page of tiles, one per app, each with a green or red light that shows whether it's working.

Behind that simple page is a small, professional-grade setup that runs at home instead of in a paid cloud. The easiest way to picture it is an apartment building:

2. The physical equipment

Everything runs on a handful of devices in the house. No monthly cloud-server bill is involved, apart from small services such as email delivery and the domain name.

DeviceWhat it isIts job
openclawSmall PC (Intel i5, 8 GB memory)The cluster's "control plane": the computer the building manager works from. It also runs a few light apps.
worker-01 and worker-02Small PCs (Intel i7, 16 GB memory, built-in Intel graphics)Do most of the work. The graphics chip on worker-02 runs the camera AI (spotting people and cars). worker-02 also has a carefully fenced connection to the smart-device Wi-Fi.
Synology RT2600ac routerThe home router, with two 4 TB drives attachedConnects the house to the internet. Keeps three separate networks (family, guests, smart devices) and stores the nightly backups.
Cameras2 Reolink, 3 Blink (plus 6 not yet installed), 2 WyzeWatch the garage, basement, parking lot, front door and porch. The Wyze Cam Pans aren't connected yet.
Why three computers instead of one? If one computer fails or needs a restart, the building manager moves its apps to the others, and each app's data is already copied onto more than one machine. One big computer would be a single point of failure.

Three separate home networks

The router keeps the family network, the guest network and a smart-device network (cameras, plugs and similar) walled off from each other. Cheap smart devices are a common way in for attackers, so they live on their own network and can't reach the family's computers. The one deliberate exception, a connection from worker-02 for the Wyze cameras, has its own firewall that only accepts traffic from those two cameras.

4. The foundation: running many apps on three computers

Each app is packaged as a container: a sealed box holding the app and everything it needs to run, so it behaves the same on any computer. Think of a shipping container: the crane doesn't care what's inside.

Kubernetes (k3s) building manager

Spreads the containers across the three computers, restarts any that crash, and replaces one when a new version arrives. k3s is a lightweight edition suited to small computers.

Like a building manager who keeps every apartment occupied and fixes anything broken.

Calico internal roads

The private network that lets apps talk to each other inside the cluster. It also enforces network rules, such as "only the CRM may talk to the CRM's database".

Like hallways with locked doors between wings.

MetalLB street addresses

Gives some apps a fixed address on the home network, so devices in the house can find them.

Like assigning unit numbers.

Traefik front desk

Receives every web visit and sends it to the right app by name, for example "frigate…" to the camera app. It can ask Authentik to check ID first.

Like a receptionist directing visitors.

Docker images on GitHub (GHCR) warehouse

Finished app packages (container images) are stored in GitHub's container registry, each labelled with its version, for example Petros 2.4.4.

Like a warehouse of prefabricated apartments, each with a model number.

PostgreSQL filing cabinets

The database most apps use: the hub, CRM, Investco and Authentik each have their own. Petros uses a hosted one (Supabase), with a nightly copy kept at home.

Like each business keeping its own locked filing cabinet.

Why it matters Without Kubernetes, someone would have to start every app by hand, notice crashes and restart them, and rebuild everything after a computer failure. With it, the cluster heals itself: a crashed app is back in seconds, usually before anyone notices.

5. Getting in safely from the internet

Most home setups "open a port" on the router so the internet can reach a computer inside. That's like leaving a side door unlocked. Home Lab Hub doesn't do this.

Cloudflare guarded entrance

Owns the public face of every address ending in energiapower.llc. It provides the padlock (HTTPS encryption), blocks obvious attacks, and hides the house's real internet address.

Cloudflare Tunnel private corridor

A small program inside the cluster dials out to Cloudflare and keeps that line open. Visitors' traffic comes back down this line, so the router never has to accept connections from strangers.

Each public address (hub, crm, ai, home, frigate…) is a "route" in the Cloudflare dashboard that says which app inside should receive it. Admin-only tools such as Argo CD have no public route at all, so they can only be reached from inside the house.

Why it matters The router has no open doors, and the house's address isn't published. An attacker scanning the internet finds nothing to knock on. Everything they could reach goes through Cloudflare first, then through a login.

6. Sign-in and who can see what

Authentik ID office

The central sign-in service at auth.energiapower.llc. It checks a password and a 6-digit code from a phone app (two-factor sign-in). It decides which groups a person belongs to: administrators, hub-family (all family apps), or hub-limited (fewer apps). New people join by invitation only.

Single sign-on one badge, many doors

Signing in to the hub also signs you in to the protected tools (Frigate, Prometheus, Alertmanager, Longhorn) without typing your password again. The most dangerous tool, Longhorn, which can delete backups, asks for a fresh phone code every time anyway.

Two kinds of apps

Protected by AuthentikFrigate, Prometheus, Alertmanager and Longhorn have no login of their own. Traefik asks Authentik "is this person allowed?" before letting anyone near them.
Their own loginCRM, Investco, Petros, PDF Edit, Godseye, Grafana and Home Assistant already have proper logins (and the phone app for Home Assistant). The hub simply links to them, to avoid signing in twice.
Why it matters A stolen password alone isn't enough to get in, because the phone code is also needed. Each family member sees only the tiles meant for them. And there is one place to remove someone's access, instead of a dozen separate accounts.

7. From a code change to a live app

Every app and every setting is written down as text in GitHub (the "blueprints"). Nobody changes the live system by hand. They change the blueprint, and machines do the rest. This is called GitOps.

GitHub blueprints

Keeps every version of every file, so any change can be seen, explained, and undone.

GitHub Actions quality gate

Runs each app's automated tests on every change. For Petros these are 15 simulation-engine checks plus browser tests driven by Playwright, a robot that clicks through the site like a person.

Argo CD foreman

Constantly compares the cluster with the blueprints. If someone changes something by hand, it puts it back; if the blueprint changes, it applies it.

Sealed Secrets locked envelopes

Passwords can't be stored in plain text on GitHub. They are sealed with a key that only the cluster has, so the blueprints can be shared safely.

Renovate update reminders

Watches for new versions of the building blocks and suggests updates to the hub, so security fixes aren't missed.

Security scanners inspectors

Trivy (known weaknesses in packages), Gitleaks (passwords accidentally saved) and Semgrep (risky code patterns) check the hub's code before it ships.

Why it mattersChanges are tested before they go live, every change is recorded and can be reversed, and the whole system could be rebuilt from the blueprints if the hardware were lost.

8. Keeping data safe: storage and backups

Apps come and go, but their data (customer records, contracts, settings, camera recordings) has to survive.

Longhorn storage units

Gives each app a "volume" (its disk) and keeps copies of it on more than one computer, so a failed computer loses nothing. It also takes the snapshots and backups.

Nightly backups off-site vault

Every night at 3:30 the important volumes are copied to the router's drives. The hub's Backups page shows when each app was last saved, and an email alert goes out if a backup fails or is overdue.

Petros nightly export copy of a cloud app

Petros keeps its database with a hosted service (Supabase) and its trained AI models with Google Cloud. Every night a job copies both to a volume at home, which then goes into the backups as well.

Restore tests fire drills

A backup is only useful if it restores. Scripts restore the newest backup into a separate test area and compare it with the live data. The CRM test on Nov 9 brought back all 45 tables; the only differences were rows added since 3:30 that morning.

A copy outside the house

The router sits in the same house as the cluster, so a fire, flood or theft could take both. Since November 13, every night at 5:30 the router's backups and the cluster's own "memory" (its list of every app, setting and password) are also copied to Cloudflare R2, an online storage service.

Cloudflare R2 bank vault in another town

Holds an encrypted copy: Cloudflare sees only scrambled data, even the file names. About 1.4 GB today, expected to settle at 2.5–4 GB, inside the free 10 GB. It can be switched off at any time by deleting the data.

Password and salt the vault key

The copy can only be read with two values kept in the owner's password manager. If the house, the computers and the router were all lost, those two values plus a new Cloudflare key are enough to bring everything back.

Second-chance window undo for ransomware

If files on the router are changed or deleted (by mistake, or by ransomware), the off-site copy keeps the old versions for 14 days instead of copying the damage over them.

Checked every night count the boxes

The last step of each run compares every file on the router with the online copy. The first run on Nov 13 matched all 3,125 files, and an email alert goes out if a run fails.

Why it mattersThree layers now: undo points on the cluster, a nightly copy on the router, and an encrypted copy outside the house. Photos, videos and music have their own copy on the router's second drive (section 11).

9. Watching over everything: monitoring and alerts

Prometheus sensors

Every few seconds, records measurements from every computer and app: memory, disk space, whether each app is running, whether backups succeeded.

Alertmanager alarm company

When a measurement crosses a line (disk nearly full, an app down, a backup overdue), it sends an email.

Grafana dashboard

Turns the measurements into charts, for example memory use per computer over the last week.

Loki diary

Collects every app's log messages in one place, searchable from Grafana. This is how problems like "why did the camera stop?" get diagnosed.

The hub's own status lights and Health page give the everyday view: green if an app answers, red if it doesn't, plus each computer's load. Prometheus and Grafana are for digging deeper.

Why it mattersProblems get noticed by a machine, often before a person would. And when something does break, the logs and measurements show what happened instead of leaving people to guess.

10. Cameras and the smart home

Cameras from three brands each work differently. The goal is one place to see them all, recordings when something happens, and alerts that matter.

Home Assistant control panel

The smart-home app at home.energiapower.llc: all cameras on one page, the parking lot light button, and automations such as "chime when someone's in the parking lot". It has its own login with a phone code, and works with the phone app.

Frigate recorder with eyes

Records the cameras around events and uses AI (OpenVINO on an Intel graphics chip) to recognise people and cars. It keeps clips for a limited time so the disk never fills up.

Neolink translator

The Reolink E1 cameras speak their own language; Neolink translates it into the standard camera format (RTSP) and passes pan/tilt commands back.

Blink bridge custom-built

Blink cameras only stream through Blink's cloud. This bridge, written for this project, starts live views on request. The battery cameras only wake when someone asks, to save battery. The wired parking lot camera stays live, and the bridge passes the video to Frigate through go2rtc, a video relay.

Mosquitto (MQTT) message board

A tiny message service the camera tools use to talk to Home Assistant: "person detected", "start live view", "light on".

Browser Mod speaker in the browser

An add-on that lets Home Assistant play the parking-lot chime in a computer's browser while the dashboard is open, with an on/off bell button.

Not working yet: the Wyze Cam Pans (they don't answer the bridge built for them). The Blink doorbell's live view depends on its weak Wi-Fi connection.

11. Your files on the router

The router has two 4 TB drives. The first holds the family's photo, video, music and Public_WD folders. The second holds backups: the cluster's nightly backups and, since November 13, a full copy of photo, video and music in a folder called media-backup. The hub's Files page shows the first drive's folders in any web browser, with the same sign-in as everything else.

The organizer mail room

Every night at 3 AM the hub moves new photos and videos from uploaded media into photo/Year/Year-Month or video/Year/Year-Month, using the date the picture was taken. It checks each copy arrived whole before removing the original. Admins can also run it by hand.

Backup to media-backup a twin on the second drive

Right after sorting, and every night, new and changed files in photo, video and music are copied to the same folders on the second drive. Nothing is ever taken off the first drive. Files you delete on the first drive are listed on the Files page; they leave the backup only after you review and confirm them.

The hub's Trash second chance

Deleting in Files moves things to the Trash (Manage › Trash) for 30 days, so a mistake can be undone. After 30 days they're removed for good.

Router recycle bins the hidden pile

The router used to keep its own recycle bin in each folder, which nothing showed. By November it held 153 GB, mostly copies the organizer had already moved. The bins are now switched off, and the Trash page shows what's left in them, with buttons to restore or empty.

Good to knowThe first full copy to media-backup takes several hours, because the router does all the reading and writing. After that, each night copies only what changed. In November a suspicious program was found and removed from the music folder while the drives were being compared; nothing similar was found anywhere else.

12. Your home PCs from anywhere

Admins can use the home PCs from any web browser: see the screen, type and click, open a command window or move files. This uses MeshCentral, which runs on the cluster. It works with Windows 11 Home, which can't accept the usual Windows "Remote Desktop".

MeshCentral remote control

A small program (the "agent") on each PC keeps a connection out to MeshCentral, so no doors are opened on the router. Signing in uses the hub's login and always asks for a fresh 6-digit code. Every session is recorded and kept for 30 days.

Wake-on-LAN remote power button

A sleeping or switched-off PC can't be reached, so Manage › Computers has a Wake button. It asks a small helper on the home network to send the PC's network card a "wake up" signal. It works best over a wired connection, and must be enabled in the PC's BIOS and network settings.

  1. Open Manage › Computers and click Wake next to the PC.
  2. Wait about a minute for it to start.
  3. Click Remote desktop, enter your 6-digit code, and pick the PC.
Still to doThe web address for MeshCentral isn't connected to Cloudflare yet, no PCs have the agent installed, and no PCs are listed in Manage › Computers. Each PC also needs Wake-on-LAN switched on in its BIOS.

13. Five everyday stories, start to finish

A. Opening the CRM from a coffee shop

  1. You type hub.energiapower.llc. Cloudflare answers with the padlock and passes the visit down the private tunnel.
  2. Traefik sees "hub" and hands the visit to the hub portal, which sends you to Authentik to sign in: password, then the 6-digit code from your phone.
  3. The hub shows the tiles your group may see, with green lights because each app answered its health check seconds ago.
  4. You click CRM. It opens crm.energiapower.llc, which arrives through the same tunnel. The CRM has its own login and reads your customers from its database in the cluster.

B. A car pulls into the parking lot

  1. The Blink camera's live video flows through Blink's cloud to the bridge, and on to Frigate.
  2. Frigate's AI spots a car and posts "car in parking lot" on the MQTT message board.
  3. Home Assistant sees it. Because the bell is switched on, it tells Browser Mod to play the chime and show "Car in the Parking Lot" in every registered browser.
  4. Frigate keeps a clip of the event. You can tap the Parking Lot card to watch live, and switch the light on.

C. A Petros improvement ships

  1. A change to Petros is saved to GitHub.
  2. GitHub Actions builds the app and runs every test inside it. One failure, and it stops there, with nothing changed.
  3. If all pass, the package is stored as the next version (for example 2.4.4) and the blueprint is updated to use it.
  4. Argo CD notices within minutes and swaps the old version for the new one. The login page now shows v2.4.4.

D. 3:30 AM, every night

  1. Longhorn copies each important volume to the router's drives: the CRM, hub, Authentik and Investco databases, Godseye's accounts, the Petros export, Home Assistant, Frigate's settings, the clip index and MeshCentral. Grafana isn't included any more: everything in it can be rebuilt from the blueprints.
  2. Prometheus records whether each backup worked. If one fails, or a backup is overdue, Alertmanager emails the admin.
  3. At 5:30 the router's backups and the cluster's memory are encrypted and copied to Cloudflare R2, then checked file by file.
  4. In the morning, the hub's Backups page shows the time of every last successful save.

E. A photo from your phone

  1. You take a photo. When the phone is on the home Wi-Fi, the DS File app uploads it to Public_WD/uploaded media on the router.
  2. At 3 AM the hub's organizer reads the date it was taken and moves it to, for example, photo/2026/2026-11, checking the copy before removing the upload.
  3. As soon as the organizer finishes, the backup copies the new photo to media-backup/photo/2026/2026-11 on the second drive.
  4. If you later delete it from the photo folder, the Files page lists it as "removed from the main drive", and it leaves the backup only when you confirm.

15. What's next, and what's being locked down

The project is built in phases. Phases 0–3 and 6 are finished, Phase 5 is built and waiting for setup on the PCs, Phase 4 is mostly done, and Phase 7 (hardening) is under way.

PhaseWhat it addsStatus
4 · Devices & camerasRemaining: the Wyze cameras, more smart devices (plug, chiller, bulbs, thermostat, locks, garage door, solar), and copying important clips to the router.Mostly done
5 · ComputersReach the family's PCs from the hub in a web browser (remote desktop), behind the same sign-in and phone code (section 12).Built; PC setup to do
6 · Router storageUse the router's two 4 TB drives from the hub: browse files, sort phone uploads, Trash, and a copy of photo, video and music on the second drive (section 11).Done
7 · HardeningA security pass: an off-site copy of the backups, tighter rules between apps, password rotation, proper certificates inside the cluster, and relief for the busy control-plane computer.In progress

Locking things down (Phase 7 so far)

Safety rules for apps building code

Each group of apps now has a safety level that the cluster enforces. The strictest groups (the hub, Argo CD, Traefik) may not run as an all-powerful user or reach into the computer underneath; device and storage tools that genuinely need more are flagged for review.

Off-site backup done

An encrypted copy of every backup outside the house, checked every night (section 8).

Walls between apps in progress

Today any app can talk to any other. The cluster is recording which apps really talk to which, so that "nothing unless allowed" rules can be added one group at a time without breaking anything. Then a broken-into app couldn't reach the databases of others.

Still to come the rest of the list

Proper certificates inside the cluster, encrypting stored passwords, a schedule for changing them, checking that only signed app packages run, and a backup for the busy main computer.

Related projectsMLflow for tracking Petros's AI training experiments, and an energy-broker AI agent that turns requests for proposals into contracts. Both would run on this same platform and appear as tiles on the hub.

16. Glossary

App / service
A program people use through a web browser, such as the CRM.
Backup
A copy of data kept somewhere else, to bring it back after a loss.
Cluster
Several computers working together as one system.
Container
An app packed with everything it needs, so it runs the same anywhere.
Control plane
The part of the cluster that makes the decisions; here, the computer "openclaw".
Database
Organised storage for records, such as customers and contracts.
Deploy
Put a new version of an app into use.
DNS / domain
The internet's address book; energiapower.llc is the domain.
Encryption (HTTPS)
Scrambling traffic so only the two ends can read it; the browser's padlock.
GitOps
Running a system by changing written blueprints that machines then apply.
Image
A finished, versioned app package ready to run as a container.
Log
An app's diary of what it did and what went wrong.
MQTT
A lightweight messaging system for smart devices.
Network policy
A rule saying which apps may talk to which.
Node
One computer in the cluster.
Pod
A running copy of an app (one or a few containers) on a node.
Restore test
Bringing a backup back into a test area to prove it works.
RTSP
A standard way for cameras to send live video.
Single sign-on (SSO)
Signing in once to use several apps.
Snapshot
A quick "undo point" for a disk, kept on the cluster.
Tunnel
A private line the cluster opens out to Cloudflare, so nobody has to connect in.
Two-factor sign-in (2FA)
Password plus a one-time code from your phone.
VLAN
A separate network on the same router, such as the smart-device network.
Volume
An app's own disk, managed by Longhorn.
